## Decision and rationale

The maintainer agreed that **v0.13.0 is the next candidate version**, conditioned on completing and formally accepting the bounded guided documentation generation experience. The `0.13.0` minor increment is a planning candidate for additive features beyond v0.12.0, not an issued tag, promised date, frozen feature list, approved Release Scope or authorization to publish.

This distinguishes the strategic preference for a coherent usable version from the technical fact that the Generator Core and Composition Preview already run on `main`. The first human walkthrough succeeded technically but the maintainer described usage as difficult; do not treat that walkthrough as GEN-15 acceptance.

## Release decision gates

Before proposing publication:
1. Complete only independently authorized UX units and verify each merged `main` baseline with green CI, including Ubuntu/Windows validation, Component catalog parity and generated-document byte parity.
2. Obtain an actual maintainer walkthrough and an explicit acceptance decision for the revised user experience (GEN-15 / UXG-11).
3. Review an evidence matrix for UXG-01–UXG-12 and GEN-01–GEN-16, limitations and remaining risks, then obtain explicit final delivery acceptance.
4. Prepare a **separate** v0.13.0 Release Scope and notes against an exact candidate commit; verify changelog, compatibility, published-versus-unreleased boundary and release metadata.
5. Obtain an **independent explicit authorization** for a tag on a named commit and publication of the GitHub Release. A clean CI alone is not approval.

No release date or milestone is committed. Do not create a tag, GitHub Release, Sprint or milestone from this decision. The published version remains v0.12.0 until a later separately approved publication.
